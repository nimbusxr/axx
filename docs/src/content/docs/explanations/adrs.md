---
title: Architecture decisions
description: The architecture decision records (ADRs) behind Axx's public contracts - building in Go, the CLI contract, releases, the docs platform, the license, value semantics, Go packs, pinned versions, coverage and the axx host.
---

Decisions that shape Axx's public contracts are recorded as ADRs in [`docs/adr`](https://github.com/nimbusxr/axx/tree/main/docs/adr), in [MADR](https://adr.github.io/madr/) format. A change to step text, the CLI JSON output or exit codes, the `axx.yaml` schema, or the release and versioning policy needs a new ADR.

| ADR | Decision | In short |
| --- | --- | --- |
| [0001](https://github.com/nimbusxr/axx/blob/main/docs/adr/0001-build-in-go.md) | Build Axx in Go with its own Cucumber executor | One static binary; built on the official Cucumber Go libraries; step text is public API. |
| [0002](https://github.com/nimbusxr/axx/blob/main/docs/adr/0002-step-protocol.md) | Language-agnostic step protocol: JSON-RPC 2.0 over stdio | Superseded by 0009. |
| [0003](https://github.com/nimbusxr/axx/blob/main/docs/adr/0003-cli-contract.md) | CLI contract: JSON envelope, exit codes, error codes | Frozen exit codes, one `--json` envelope for every command, stable `AXX-Exxxx` codes, compact output for agents. |
| [0004](https://github.com/nimbusxr/axx/blob/main/docs/adr/0004-versioning-and-release.md) | Versioning and release: `v0.x` pre-releases via release-please and GoReleaser | Every `0.x` release is a GitHub pre-release; signed, SBOM'd binaries, container images and a Homebrew cask; the criteria for `v1.0.0`. |
| [0005](https://github.com/nimbusxr/axx/blob/main/docs/adr/0005-docs-platform.md) | Docs platform: Starlight, generated reference, agent-first outputs | This site: Starlight, reference generated from the binary, Markdown twins (which agents asking for Markdown get at a page's address, from CloudFront), `llms.txt`, skills and an MCP server. |
| [0006](https://github.com/nimbusxr/axx/blob/main/docs/adr/0006-license.md) | License Apache-2.0 with DCO | Apache-2.0, contributions signed off with the DCO. |
| [0007](https://github.com/nimbusxr/axx/blob/main/docs/adr/0007-java-compatibility-layer.md) | Value semantics of the established Java libraries, verified by recorded oracles | JSONPath, regular expressions and number formatting follow Jayway JsonPath, `java.util.regex` and Jackson; the few deliberate deviations are listed in one place. What a step's value means is ADR 0014's. |
| [0008](https://github.com/nimbusxr/axx/blob/main/docs/adr/0008-publish-from-release-workflow.md) | Publish every component from `release.yml`, gated on release-please outputs | The CLI, the WireMock image and the IntelliJ plugin publish from one workflow; nothing publishes unless the `AXX_PUBLISH` repository variable is `true`. |
| [0009](https://github.com/nimbusxr/axx/blob/main/docs/adr/0009-go-packs.md) | Custom steps are Go packs; the `axx` executable loads the packs a project uses | Packs are opt-in per project (`axx-packs.yaml`), and `axx` builds itself with them; custom packs work on the same public contexts as Axx's own. |
| [0010](https://github.com/nimbusxr/axx/blob/main/docs/adr/0010-payload-properties-create-missing-objects.md) | Setting a payload property creates the objects its path lacks | `recipient.name` in a payload without `recipient` creates it, unlike Jayway JsonPath; paths through arrays still need the array. |
| [0011](https://github.com/nimbusxr/axx/blob/main/docs/adr/0011-desktop-apps-through-the-accessibility-tree.md) | Desktop apps are tested through the operating system's accessibility tree | Drivers axx writes in Go read the tree every app publishes for screen readers, on all three operating systems: black-box, with no change to the app. |
| [0012](https://github.com/nimbusxr/axx/blob/main/docs/adr/0012-one-vocabulary-for-apps-and-a-file-context-for-everything-under-test.md) | Every app is driven with the same steps, and everything under test has a file context | `app-core` words the steps every app takes once, over the mobile and desktop packs; a folder says whose it is, so files resolve in that service's or app's own context. |
| [0013](https://github.com/nimbusxr/axx/blob/main/docs/adr/0013-phones-through-their-drivers-served-by-device-hosts.md) | Phones are driven through their own drivers by axx, and served by device hosts (proposed) | axx installs and talks to the drivers on the devices itself, built around a host boundary, so the same code drives a device in the axx process or serves it to runs elsewhere. |
| [0014](https://github.com/nimbusxr/axx/blob/main/docs/adr/0014-a-value-means-what-it-says.md) | A value means what it says, in every pack | `42` is an integer and `"42"` the string, in every pack, set or checked; checks are strict, nothing is inferred, and an empty cell or a number JSON lacks (`01067`) fails with the explicit forms. |
| [0015](https://github.com/nimbusxr/axx/blob/main/docs/adr/0015-a-project-names-the-axx-version-it-runs-on.md) | A project names the Axx version it runs on; the installed Axx hands over to it | `axx.yaml` may name one exact release (`axx: 0.5.0`). The installed Axx downloads it, checked against its checksums, and hands over to it before it parses anything; the axx host follows it. |
| [0016](https://github.com/nimbusxr/axx/blob/main/docs/adr/0016-a-macos-launcher-is-the-one-identity-a-person-allows.md) | On macOS, Axx runs desktop scenarios under a launcher of its own, the one identity a person allows (proposed) | A small launcher, signed with NimbusXR's Developer ID and notarized, runs Axx and the apps under test as its children, so a person allows macOS's permissions once, whatever terminal, editor or CI agent started Axx. |
| [0017](https://github.com/nimbusxr/axx/blob/main/docs/adr/0017-a-run-measures-the-coverage-of-the-system-under-test.md) | A run measures the coverage of the system under test, through one pack per runtime | `axx run --coverage` measures the services a run starts, per run and never per scenario, in one report; minimums are checked on runs of every scenario only, and a run under one exits 6. |
| [0018](https://github.com/nimbusxr/axx/blob/main/docs/adr/0018-a-pack-has-a-side-in-the-axx-host.md) | A pack has a side in the axx host, and web-core's starts the browser a sandbox keeps from starting | A pack's side in the host gives an agent's run only what its sandbox would let it have: the host starts the browser, its network goes through the run, and Playwright's server gets the web steps' commands and no other. |
| [0019](https://github.com/nimbusxr/axx/blob/main/docs/adr/0019-devices-and-apps-start-in-the-axx-host-once-approved.md) | Devices and desktop apps start in the axx host, each app once its person approved it | An app is the agent's code outside its sandbox, so a person approves each app before the host starts it; beyond the app, a run asks only for what a step does, and the files it names must be the project's. |
| [0020](https://github.com/nimbusxr/axx/blob/main/docs/adr/0020-a-scroll-is-asked-of-the-view-a-swipe-is-a-finger.md) | A scroll is asked of the view; a swipe is a finger (proposed) | A step scrolls by asking the view, through an accessibility service of Axx's own on Android and XCTest's scroll to an element on iOS, and swipes only where a view cannot be asked. |
| [0021](https://github.com/nimbusxr/axx/blob/main/docs/adr/0021-a-pack-can-be-experimental.md) | A pack can be experimental | A new feature arrives as a pack that may still change: adding the pack is the opt-in, Axx says what it is wherever a project meets it, and it adds no exit code and no `--json` field until it is stable. |
| [0022](https://github.com/nimbusxr/axx/blob/main/docs/adr/0022-scenarios-claim-controls-and-a-report-shows-what-covers-each.md) | Scenarios claim controls, and a report shows what covers each | An application team proves its controls with its own scenarios, marked with tags, and the security team owns the list of required controls; frameworks, report formats and sources of evidence are packs, and the gate is a command that judges a run's or several runs' evidence. |
